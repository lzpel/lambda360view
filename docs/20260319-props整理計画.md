# Props整理計画

作成: 2026-03-19

## 方針

「無意味に柔軟な設定は排除する」。実際のモデリングソフト・CADのユースケースでカバーできる範囲に絞る。

---

## 1. 共通型 `Axis` の導入

```ts
export type Axis = 'X' | 'Y' | 'Z';
```

この型を `axisUp`・`axisGround`・`axisCenter` の共通型として使う。命名はプレフィックス方式（`axisUp`）で統一し、IDEの補完でグループ化できるようにする。

---

## 2. `upAxis` → `axisUp` に変更・型を絞る

**変更前:**
```ts
upAxis?: 'Y' | 'Z' | '-Y' | '-Z';
```

**変更後:**
```ts
axisUp?: Axis; // 'Y' | 'Z' のみ実質使用（デフォルト: 'Y'）
```

- `-Y`・`-Z` を廃止: 主要ソフト（Blender, AutoCAD, Maya等）でX/Y/Z上軸以外を使うものは存在しない
- `X` 上軸も廃止対象だが、型は `Axis` で統一するため残る（実際に `X` を渡すユーザーはいないはず）
- `getUpAxisRotation()` の `-Y`・`-Z` ケースを削除

---

## 3. `axisGround` の追加

モデルのバウンディングボックス底面を、指定軸方向の0に揃える。

```ts
axisGround?: Axis; // デフォルト: axisUp と同じ軸
```

- `axisGround='Y'` → バウンディングボックスの Y最小値 が 0 になるよう移動
- `axisGround='Z'` → バウンディングボックスの Z最小値 が 0 になるよう移動
- デフォルトは `axisUp` と同じ軸（上が Y なら地面も Y）
- 実装: モデルロード後、バウンディングボックスを計算してシーンのオフセットを適用

---

## 4. `axisCenter` の追加

指定した軸方向にモデルを中央揃え（バウンディングボックスの中心を原点に）する。

```ts
axisCenter?: Axis[]; // 例: ['X', 'Z']（デフォルト: undefined = 変換なし）
```

- `['X', 'Z']` → 水平面で中央揃え（CADモデルでよくある用途）
- `['X', 'Y', 'Z']` → 全軸中央
- 実装: `axisGround` と同じタイミング（モデルロード後）でオフセットを適用

### `axisGround` と `axisCenter` の優先順位

同じ軸が両方に指定された場合、`axisGround` を優先する。
例: `axisCenter={['X', 'Y', 'Z']}` かつ `axisGround='Y'` → Y軸は底面0揃え、XZは中央。

---

## 5. `preserveCamera` の廃止

モデル切り替え時にカメラを維持するかどうかをユーザーが制御する必要はなく、ビューワーが判断すべき挙動。実際に `false` を使うユースケースが想定できないため廃止。

---

## 6. 変更後の `Lambda360ViewProps` 全体像

```ts
export type Axis = 'X' | 'Y' | 'Z';

export interface Lambda360ViewProps extends Omit<React.HTMLAttributes<HTMLDivElement>, 'children'> {
    model: ArrayBuffer | null;
    nodeCenter?: React.ReactNode;
    nodeFooter?: React.ReactNode;
    backgroundColor?: string;
    edgeColor?: string;
    showEdges?: boolean;

    axisUp?: Axis;        // デフォルト: 'Y'
    axisGround?: Axis;    // デフォルト: axisUp と同じ軸
    axisCenter?: Axis[];  // デフォルト: undefined

    orthographic?: boolean;
    showViewMenu?: boolean;
    annotations?: Annotation[];
}
```

## 7. 実装順序

1. `Axis` 型を `types.ts` に追加
2. `upAxis` → `axisUp` にリネーム、型を `Axis` に変更、`getUpAxisRotation()` を修正
3. `preserveCamera` を削除、カメラ初期化を命令的に一度だけ行う方式に変更
   - 現状: `<PerspectiveCamera position={cameraConfig.position} />` が毎回 position props を受け取るため、モデル切り替え時にカメラがリセットされる。それを `requestAnimationFrame` で上書き復元するという脆弱な実装になっている
   - 変更後: `position` props を `<PerspectiveCamera>` / `<OrthographicCamera>` から除去し、初回ロード時（`prevSceneRef.current === null`）だけ `camera.position.set(...)` を命令的に呼ぶ
   - 2回目以降のモデル切り替えではカメラに触れないため、カメラは自然に維持される
   - `rAF` によるカメラ復元ロジックも不要になり削除
4. `axisGround`・`axisCenter` を追加
   - モデルロード後のバウンディングボックス計算箇所（`SceneManager` 内の `cameraConfig` 計算）に合わせてオフセット適用
   - アノテーション座標はモデル空間基準のまま変わらないため、`<group>` のオフセットとして適用し透過的に扱う

---

## 8. バグ: 初回ロード時にOrbitControlsが効かない

### 症状
初回モデルロード後、ビュー切り替えを一度行うまでOrbitControlsがマウス操作を受け付けない。

### 原因
`SceneManager` は `displayScene && cameraConfig` が揃うまで `null` を返す。
揃った瞬間に初めてJSX（Camera・OrbitControls）がレンダリングされ、Reactのエフェクトが以下の順で実行される：

1. drei `<PerspectiveCamera makeDefault>` のエフェクトが走り、カメラがデフォルト位置でセットアップされる
2. **`SceneManager` のカメラ初期化エフェクトが `controls=null` の状態で発火する**
   - `camera.position.set(...)` は実行される ✓
   - `controls` が null のため `orbitControls.update()` は実行されない ✗
   - `cameraInitializedRef.current = true` がセットされる
3. drei `<OrbitControls makeDefault>` のエフェクトが走り、`controls` が fiber ストアに登録される
4. `controls` の変化でカメラ初期化エフェクトが再発火するが、`cameraInitializedRef.current === true` のため早期リターン

結果：OrbitControls は手順1のデフォルトカメラ位置を基準に内部の球面座標を初期化する。手順2で位置は移動されているが、OrbitControls の内部状態が同期されていないため、操作時に誤った位置に戻ろうとする。

ビュー切り替え時に `orbitControls.update()` が呼ばれることで初めて内部状態が同期され、以降は正常に動作する。

### 修正方針
`<OrbitSizeControls maxSize>` コンポーネント（`components/OrbitSizeControls.tsx`）を新設し、カメラのサイズ・距離管理を集約する。

```tsx
<OrbitSizeControls maxSize={maxSize} />
```

`OrbitSizeControls` は内部で `<OrbitControls>` を子としてレンダリングする。Reactは子のエフェクトを親より先に実行するため、`<OrbitControls>` の `makeDefault` エフェクトが必ず先に走り `controls` がストアに登録された後、`OrbitSizeControls` 自身のエフェクトが発火する。兄弟の記述順に依存せず構造的に保証される。呼び出し側も1ノードで済む。

**`OrbitSizeControls` の責務：**
- `calcCamera(maxSize)` 相当の計算を内包
- 初回（`controls` が非nullになったとき）: カメラを正しい初期位置にセットし `controls.update()` を呼ぶ
- `maxSize` 変化時（モデルスワップ）: カメラの現在方向ベクトルを保ったまま距離だけスケール、near/far を更新し `controls.update()` を呼ぶ

**`SceneManager` 側の簡略化：**
- `cameraConfig` useMemo → `maxSize` のみに削減
- `cameraInitializedRef` と複数のカメラ初期化エフェクトを削除
- `calcCamera()` を `OrbitSizeControls` 内に移動

---

## 9. 注意点

- `axisGround`・`axisCenter` の適用は `<group rotation={upAxisRotation}>` の子 `<group position={offset}>` として実装し、アノテーションの `getWorldPosition()` による座標解決と干渉しないようにする
